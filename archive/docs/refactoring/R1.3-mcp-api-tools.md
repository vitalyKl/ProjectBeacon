# R1.3 — Split McpApiTools

## Goal

Split `ProjectBeacon.Cli/Mcp/McpApiTools.cs` by MCP domain.

## Target groups

- project;
- task;
- pipeline;
- context;
- decisions;
- review;
- models.

Suggested files:
- `McpProjectTools.cs`
- `McpTaskTools.cs`
- `McpPipelineTools.cs`
- `McpContextTools.cs`
- `McpDecisionTools.cs`
- `McpReviewTools.cs`
- `McpModelTools.cs`

Keep a small common `McpApiTools.cs` only where shared registration/dispatch is genuinely needed.

## Hard constraint

MCP public contract must remain identical:
- tool names;
- arguments;
- results;
- errors;
- scope/auth semantics.

No new abstraction framework.
No protocol redesign.

Run MCP tests plus full suite and formatting.
